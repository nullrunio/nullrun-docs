Material's stock footer is replaced (not extended) because its default chrome — "Made with Material for MkDocs", social-icon row, prev/next pager — is off-brand for this design and, in the pager's case, actively misleading: `navigation.footer` is off in mkdocs.yml, so the pager would render links that don't reflect the actual reading order. What lives here, and why each item: copyright Legal attribution. `config.copyright` is unset in mkdocs.yml, so the year and product name are composed here — a static string is honest about a site that has no licence file to point at. GitHub The repo. `config.repo_url` is already set (it drives the menu-bar button and the per-page edit link), so this reuses it rather than hard-coding a URL that could drift. Support mailto: into the product's support inbox — the same address docs/concepts/billing.md already documents. Status Deliberately NOT a link. The site has no status page; compliance/data-handling.md lists "Status page" under what is explicitly *not* available, and inventing a URL here would contradict a page the same site publishes. Recurring outage reports belong in the GitHub issue tracker, which the GitHub link already reaches. The footer is deliberately not a sitemap. The left sidebar is the navigation; a second link farm in the footer would duplicate it and re-introduce the per-page link weight that the sidebar avoids. Template hierarchy: this file replaces Material's `partials/footer.html` via the `custom_dir: overrides` setting. -#}
